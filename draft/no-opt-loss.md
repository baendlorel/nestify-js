## 实质丢失的控制

| 能力                                              | 说明                                                                                                                                 | 现在怎么办                                                                                                                     |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| **`bodyLimit`**                                   | 按路由设置请求体大小上限（上传接口最常见）                                                                                           | 只能全局 `fastify({ bodyLimit })`；multipart 场景可用管道自己的 `limits`；别的场景得在 guard / 预处理里手动看 `content-length` |
| **`config`**                                      | 路由级自定义配置，很多 Fastify 插件靠它工作，典型是 `@fastify/rate-limit` 读 `config.rateLimit`                                      | 这类插件无法按路由配置了；框架自带 `@Throttle` 可覆盖限流场景                                                                  |
| **路由级 hooks**                                  | `onRequest` / `preParsing` / `preValidation` / `preHandler` / `preSerialization` / `onSend` / `onResponse` / `onError` / `onTimeout` | 语义上由 guard / interceptor / filter 承担，但不等价（例如 `onSend` 能改原始字节、`onRequest` 在 body 解析前执行）             |
| **`errorHandler`**                                | 路由自己的错误处理                                                                                                                   | 本来就会和 Nestify filter 抢；删掉反而更干净                                                                                   |
| **`schemaErrorFormatter` / `serializerCompiler`** | 单路由的 schema 错误格式 / 序列化编译器                                                                                              | 只能应用级 `fastify.setSchemaErrorFormatter` / `setSerializerCompiler`                                                         |
| **`logLevel`**                                    | 单路由日志级别                                                                                                                       | 只能全局，或在 handler 里用 `request.log`                                                                                      |
| **`version` / `constraints`**                     | 路由版本、host 等约束                                                                                                                | 完全失去，只能靠不同 URL 前缀区分                                                                                              |
| **`exposeHeadRoute`**                             | 自动生成 HEAD 路由                                                                                                                   | 需要显式写 `@Head()`（如果有的话）                                                                                             |
| **`summary` / `description` / `tags`**            | Swagger 的路由描述                                                                                                                   | 上一个提交删 `@ApiSchema` 时就一起没了，现在无法按路由写说明                                                                   |
