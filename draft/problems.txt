✅ 24. 路由统一以尾斜杠注册，且 `ignoreTrailingSlash` 可被关闭，导致非根路由 404
位置：packages/core/src/register/route/controller.ts:28、packages/core/src/register/route/controller.ts:37、packages/core/src/register/nestify.ts:73
测试：packages/core/tests/http-method.test.ts
复现：`nestify(App, { ignoreTrailingSlash: false })` 时 GET /probe/hello → 404，只有 /probe/hello/ 可访问。
实现：按 NestJS 语义定案——尾斜杠始终忽略，且不提供开关：
- `concatRoute` 不再为每个片段补 `/`（根路由仍为 `/`），注册的是标准 `/a/b`；
- 删除 `NestifyBootOptions.ignoreTrailingSlash` 字段；
- `nestify()` 无条件写入 `routerOptions.ignoreTrailingSlash: true`，即使调用方在 `fastify.routerOptions` 传 `false` 也会被覆盖；
- README（中英）移除该选项，并在 `fastify` 选项处注明会被强制为 `true`。
注意：直接用 `apply()` 搭配自建 `fastify()` 时，尾斜杠策略由该实例创建时的参数决定（Fastify 创建后不可修改）。

✅ 25. `useExisting` 依赖声明顺序，目标声明在后时启动报错
位置：packages/core/src/register/lazy-injector.ts:127、packages/core/src/register/lazy-injector.ts:178
测试：packages/core/tests/provider-values.test.ts
复现：providers 中把 `{ provide: 'alias', useExisting: 'late' }` 写在 `{ provide: 'late', ... }` 之前 → "Cannot find existing provider: late"。
实现：`Injector` 新增 `pendingAliases` 队列。`useExisting` 先按 token 尝试立即解析；目标尚未创建时不抛错，而是记录 `{ token, target }`。`apply()` 开头调用 `resolvePendingAliases()`：反复扫描队列，把已存在的目标写回 `instanceMap`，直到某轮没有进展，因此支持 A→B→C 的别名链；仍有残留时抛 `Cannot find existing provider`。模块可达性由 `expectAccessible` 先行校验，越界别名会先报模块隔离错误。

✅ 26. 上传文件数量 / parts / 字段数量超限返回 500，并泄露插件原始消息
位置：packages/core/src/multipart/pipes/file.pipe.ts:85、packages/core/src/multipart/pipes/file.pipe.ts:88
测试：packages/core/tests/multipart-integration.test.ts
复现：`@Files({ limits: { files: 1 } })` 上传 2 个文件 → 500 "File upload failed: reach files limit"。
实现：`PipeFile` 的 catch 先取出插件错误码再分流：`FST_REQ_FILE_TOO_LARGE`（及框架自身的 `PayloadTooLargeException`）→ 413「size limit」；`FST_FILES_LIMIT` / `FST_PARTS_LIMIT` / `FST_FIELDS_LIMIT` → 413「count limits」；`FST_INVALID_MULTIPART_CONTENT_TYPE` → 400。其余错误才包装为 `NestifyError('File upload failed: ...')`，插件原文不再以 500 泄露。

✅ 27. 未注册的过滤器 token 抛出 `getPrototypeOf` 的 TypeError
位置：packages/core/src/register/lazy-injector.ts:66、packages/core/src/register/route/middlewares/filter.ts:62
测试：packages/core/tests/filter-integration.test.ts
复现：`@UseFilters('not-registered')` → "Reflect.getPrototypeOf called on non-object"，无法定位问题。
实现：`Injector.getDetail` 先判断取到的实例是否为对象，非对象直接返回 `cls = null`（此前会对 `undefined` 调 `getPrototypeOf` 抛 TypeError）。`createFilter` 随后用 `expectClass` 断言并输出 `Filter token 'x' must refer to a registered filter class`，可在启动期定位到具体 token。

✅ 28. `JwtService.configure` 接受空密钥，与构造函数行为不一致
位置：packages/core/src/auth/jwt.ts:42
测试：packages/core/tests/jwt.test.ts
复现：`configure({ secret: '' })` 后用空密钥签名成功；构造函数中空字符串却被视为未设置。
实现：`configure()` 改为 `this.secret = options.secret || null`，与构造函数一致；空字符串 / 未提供都在 `createSignature` 处抛 `[Nestify] Secret is not set`，避免空密钥参与 HMAC。

✅ 29. JWT 载荷不是对象时未拒绝
位置：packages/core/src/auth/jwt.ts:246
测试：packages/core/tests/jwt.test.ts
复现：载荷为数组 / 原始值时 `verify` 直接返回，`exp` / `nbf` 等声明校验被跳过。
实现：`verify()` 在 `JSON.parse` 之后增加 `_isObject(payload) && !_isArray(payload)` 校验，数组 / null / 字符串 / 数字一律抛 `Invalid JWT payload`，不会再跳过 `exp` / `nbf` / `aud` / `iss` 检查直接返回。

✅ 30. `HttpMethod` 不校验方法名
位置：packages/core/src/decorators/router/http-methods.ts:22
测试：packages/core/tests/http-method.test.ts
复现：`HttpMethod(123)` → "method.toUpperCase is not a function"；`HttpMethod('')` 直到 Fastify 注册阶段才报错。
实现：`HttpMethod(method)` 先 `expectString`，再匹配 `/^[A-Za-z][A-Za-z0-9-]*$/`，最后才 `toUpperCase()` 交给 `registerRoute`；非字符串报 "HTTP method must be a string"，空串 / 含空格报 "Invalid HTTP method: ''"。

✅ 31. 响应已发送后抛异常仍会二次写 reply
位置：packages/core/src/register/route/middlewares/filter.ts:22
测试：packages/core/tests/filter-integration.test.ts
复现：handler 内 `reply.send()` 后再 throw，默认过滤器仍尝试 `status(500).send(...)`。
实现：`createDefaultFilter` 开头判断 `reply.sent`，已发送时只对非 `HttpException` 记一条 error 日志并直接返回，不再调用 `status().send()`；未发送时保持原逻辑（HttpException 用自身状态，未知异常统一 500）。

低 / 设计限制
==

32. provider 实例是应用级而非模块级，同 token 的重复声明被静默忽略
位置：packages/core/src/register/lazy-injector.ts:103、packages/core/src/register/module.ts:64
现状：两个模块都声明 `{ provide: 'shared', useValue: ... }` 时只有先注册的生效，后一个被静默丢弃（NestJS 中 provider 按模块隔离，不会冲突）。
影响：跨模块复用同一 token 会拿到非预期实例；写错配置也不会报错。
说明：改为模块级作用域需要每个模块独立 injector，属架构调整，未在本轮改动。

✅ 33. 无所谓。字符串 / symbol 型 provider 无法被 exports

✅ 34. 彻底删除 `@ApiSchema` 与 `@Opt`

35. `startCronJob` / `stopCronJob` 在 uid 重复时只作用于第一个任务
位置：packages/core/src/schedule/cron.ts:91、packages/core/src/schedule/cron.ts:100
现状：`findJob(uid)` 使用 `Array.find`，重复 `uid` 时其余任务不受控。
影响：配置错误难以发现，但不构成越权。
说明：可在注册期校验 uid 唯一，属增强项。
