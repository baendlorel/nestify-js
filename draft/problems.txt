✅ 16. 拦截器 catch 无法捕获控制器或 pipe 抛出的异常
位置：packages/core/src/decorators/middlewares/interceptor.ts:36、packages/core/src/register/route/middlewares/interceptor.ts:29、packages/core/src/register/route/handler.ts:55
测试：packages/core/tests/interceptor.test.ts
语义：对齐 NestJS 的 `catchError`，内层拦截器先捕获，未恢复时向外层传递，全部未恢复才进入 filter。

✅ 17. 叠加多个同级中间件装饰器会相互覆盖
位置：packages/core/src/register/meta.ts:49（metaPush）、packages/core/src/register/meta.ts:215、packages/core/src/register/meta.ts:234、packages/core/src/register/meta.ts:252、packages/core/src/register/meta.ts:270、packages/core/src/register/meta.ts:291
测试：packages/core/tests/middleware-stacking.test.ts
执行顺序：对齐 NestJS `extendArrayMetadata`，后应用的装饰器追加到数组末尾。
- 管道 / 守卫 / 过滤器：离 handler 最近的声明先执行（数组顺序）
- 拦截器：`intercept` 按声明顺序调用，`map` 由内向外（离 handler 最近的是最内层，最后应用）
- 内置 `@Body()` / `@File()` 与 `@UsePipes(...)` 可共存；路由 schema 取第一个带 schema 的 pipe

✅ 18. Cron 按函数身份去重，误丢弃不同实例上的相同方法
位置：packages/core/src/schedule/cron.ts:60、packages/core/src/schedule/cron.ts:129、packages/core/src/schedule/cron.ts:158
测试：packages/core/tests/cron.test.ts
实现：去重键为「实例 + 方法」（`WeakMap<实例, WeakSet<方法>>`）；每个任务是 node-cron 的独立实例，同类不同实例天然互不干扰。

✅ 19. Cron 执行过程中停止再启动会产生重复计时器
位置：packages/core/src/schedule/cron.ts:52、packages/core/src/schedule/cron.ts:69
测试：packages/core/tests/cron.test.ts
实现：自研 timer / 代次逻辑已整体删除，start / stop / destroy 直接委托给 node-cron 任务对象，不再存在重复计时。

✅ 20. 同一 controller 通过不同模块前缀导入时只注册第一条路径
位置：packages/core/src/register/route/controller.ts:83、packages/core/src/register/route/controller.ts:85、packages/core/src/register/route/controller.ts:102
测试：packages/core/tests/controller-multi-module.test.ts
NestJS 对照：允许同一 controller 声明在多个模块中（`RoutesResolver.resolve` 按模块逐个注册；`routes-mapper` 注释即「按声明它的每个模块各注册一次」）。
实现：去重键由「controller 类」改为「controller + 生效路由前缀」，不同前缀各注册一次，相同前缀仍只注册一次（避免 Fastify 重复路由报错）。

✅ 21. toModule 的构造参数被丢弃
位置：packages/core/src/decorators/module.ts:39、packages/core/src/decorators/injectable.ts:17、packages/core/src/register/meta.ts:120、packages/core/src/register/lazy-injector.ts:70
测试：packages/core/tests/to-module.test.ts
决定：按你的意见**取消 args 支持**（需要预置参数请用 factory provider）。`toModule` / `toInjectable` / `metaSetProvider*` 均去除 args，`ProviderMeta` 改为标记对象 `{ isProvider: true }`，provider 一律无参构造。

✅ 22. expectArray 忽略元素检查函数返回的错误
位置：packages/core/src/asserts/expect.ts:70、packages/core/src/asserts/expect.ts:80、packages/core/src/register/expect-module.ts:97
测试：packages/core/tests/expect-array.test.ts
实现：统一谓词返回契约 —— 返回字符串用该信息报错，返回 `false` 用外层 msg 报错，抛错原样传播。
顺带修复：`expectController` 的路径谓词原用 `_isPathNode` 会拒绝 `:id` 等合法路由参数（之前返回值被忽略所以从未生效），现改为只校验节点结构（非空且不含 `/`），语法校验仍由 `splitPath` 负责。

✅ 23. HttpMethod 没有返回装饰器工厂
位置：packages/core/src/decorators/router/http-methods.ts:21
测试：packages/core/tests/http-method.test.ts
实现：`HttpMethod(method)` 现在 `return registerRoute(method.toUpperCase())`，可用 `@(HttpMethod('HEAD')('/path'))` 声明自定义方法。
