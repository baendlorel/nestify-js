测试：packages/core/tests/provider-values.test.ts

✅ 15. useExisting 无法引用基本类型的 useValue
位置：packages/core/src/register/lazy-injector.ts:95、packages/core/src/register/lazy-injector.ts:123
测试：packages/core/tests/provider-values.test.ts

✅ 16. 拦截器 catch 无法捕获控制器或 pipe 抛出的异常
位置：packages/core/src/decorators/middlewares/interceptor.ts:36、packages/core/src/register/route/middlewares/interceptor.ts:29、packages/core/src/register/route/handler.ts:55
测试：packages/core/tests/interceptor.test.ts
语义：对齐 NestJS 的 `catchError`，内层拦截器先捕获，未恢复时向外层传递，全部未恢复才进入 filter。

✅ 17. 叠加多个同级中间件装饰器会相互覆盖
位置：packages/core/src/register/meta.ts:49（metaPush）、packages/core/src/register/meta.ts:215、packages/core/src/register/meta.ts:234、packages/core/src/register/meta.ts:252、packages/core/src/register/meta.ts:270、packages/core/src/register/meta.ts:291
测试：packages/core/tests/middleware-stacking.test.ts
执行顺序：对齐 NestJS `extendArrayMetadata`，后应用的装饰器追加到数组末尾。
- 管道 / 守卫 / 过滤器：离 handler 最近的声明先执行（数组顺序）
- 拦截器：`intercept` 按声明顺序调用，`map` 由内向外（离 handler 最近的是最内层，最后应用）
- 内置 `@Body()` / `@File()` 与 `@UsePipes(...)` 可共存；路由 schema 取第一个带 schema 的 pipe

✅ 18. Cron 按函数身份去重，误丢弃不同实例上的相同方法
位置：packages/core/src/schedule/cron.ts:34、packages/core/src/schedule/cron.ts:89、packages/core/src/schedule/cron.ts:178
测试：packages/core/tests/cron.test.ts
实现：`boundTargets` 改为 `WeakMap<实例, WeakSet<方法>>`，按「实例 + 方法」去重，同一实例重复注册仍只绑定一次。

✅ 19. Cron 执行过程中停止再启动会产生重复计时器
位置：packages/core/src/schedule/cron.ts:62、packages/core/src/schedule/cron.ts:74、packages/core/src/schedule/cron.ts:198
测试：packages/core/tests/cron.test.ts
实现：`JobData` 新增 `generation` 代次，start/stop/close 均推进代次；旧执行完成时代次不匹配则不再调度下一轮。

20. 同一 controller 通过不同模块前缀导入时只注册第一条路径
位置：packages/core/src/register/route/controller.ts:34、packages/core/src/register/module.ts:44
复现：Child 模块分别位于 first 和 second 前缀下时，/first/item 可访问，/second/item 返回 404。
原因：去重只使用 controller 类，不包含继承的模块前缀。
建议：明确同一 controller 的多前缀语义，并按有效路由或 controller+前缀去重。

21. toModule 的构造参数被丢弃
位置：packages/core/src/decorators/module.ts:39、packages/core/src/decorators/injectable.ts:17
复现：toModule(External, { args: ['expected'] }) 创建的 External 实例收到 undefined。
原因：toInjectable 接收 args，但调用 metaSetProviderOnClass 时没有传入。
建议：将参数写入 provider 元数据，并测试实例构造。

22. expectArray 忽略元素检查函数返回的错误
位置：packages/core/src/asserts/expect.ts:70、packages/core/src/register/expect-module.ts:160
复现：expectArray([1], 'bad', () => 'invalid') 不抛错。
影响：调用方依赖返回字符串报告错误的检查失效，例如模块 exports 是否属于 providers 的检查不会生效。
建议：统一谓词的返回契约并处理错误结果，或把调用方全部改为显式抛错。

23. HttpMethod 没有返回装饰器工厂
位置：packages/core/src/decorators/router/http-methods.ts:21
复现：HttpMethod('HEAD') 返回 undefined，因此不能通过公开接口声明自定义 HTTP 方法。
建议：返回 registerRoute(method.toUpperCase())，并测试装饰器注册结果。
